# 过程文档归档规范

本目录专门归档本工程的「过程文档」——审计报告、优化/修改实施记录、分析记录等，与「活文档」（指令、模板、快速启动指南等）分离管理。

## 一、归档范围

**应归档至本目录**：
- 审计报告（对工程骨架/指令/skill/模板/脚本的独立审查）
- 优化/修改实施记录（质量优化、架构调整的实施报告/改动清单/完成总结）
- 分析记录（阶段性的评估、复盘、研判文档）

**不归档（保留原位置）**：
- `README.md`、`SETUP.md` 的「更新日志 / 修改日志」章节——唯一例外的修改历史落点（承载最新变更摘要）
- `docs/快速启动指南.md`、`docs/最佳实践.md` 等活文档
- `document/` 下各项目的产物（需求/技术文档，属业务产物，非过程文档）

## 二、命名规范

```
{YYYY-MM-DD}_{工具名}_{文档名}.md
```

- **日期**：文档产生日期（`YYYY-MM-DD`）
- **工具名**：执行该审计/修改/分析的 AI 工具标识（小写，如 `workbuddy` / `claude` / `cursor`）
- **文档名**：原文档名（去掉尾部旧日期后缀）

示例：
- `2026-09-07_workbuddy_独立审计报告.md`
- `2026-09-02_claude_优化实施报告.md`

## 三、归档约定

1. 任何 AI 工具（prototype-agent / architect-agent / 其他外部工具）进行审计、修改、分析后产生的过程文档，一律写入本目录，不在根目录、docs/ 等其他位置单独存放。
2. 命名严格遵循「日期 + 工具名」规范，便于按时间与来源检索。
3. 本目录内历史文档**只归档、不改写**——如实保留历史记录原貌，禁止篡改。
4. 唯一例外：`README.md` 与 `SETUP.md` 的更新日志章节承担「最新变更摘要」职责，随变更同步追加；本目录承载完整过程文档。
