1. **权威链贯通核对**：配置（opencode.json 内联 prompt）→ 主指令 → 技能 → 模板 → 内容项（章节号 / 术语 / 相对路径 / operationId / FR-x），逐环取"上游声明的锚点"与"下游实际骨架"比对。

## 七、审计结论

1. **权威链主干成立**：配置 → 指令 → 技能 → 模板 → 内容项的**章节号 / 术语 / 锚点（FR-x、operationId、OPEN-*）**四类骨架全部对得上，`consistency-check.sh` 实测 6/6，未发现"多文件漂移"。
2. **三类真实缺陷**：
   - **基准自污染**（P0-1：`self-check` 唯一权威基准含旧标题）；
   - **废止文件活动引用**（P0-2：2 个技能 4 处引用已删的依赖清单）；
   - **权威编排自相矛盾**（P0-3：`CLAUDE.md` 核心原则 vs Step 4）。
3. **简洁性问题的根因是"重构 diff 未回收"**：技能层把上一轮的改动说明（`（新增）`、`6大改进/5大改进`、版本说明、迁移对照表）当正文保留，活文档层保留了旧基线的量化指标（token/行数/百分比）与旧版本号。**建议以"是否对下一次执行产生约束"为唯一判据做一轮回收。**
4. **静态防线需要补齐覆盖**（非增加规则）：4 个空档中，"检查 6 漏扫通用异常处理"与"产品侧无路径校验"可用 ≤10 行脚本修掉，收益最大。

### 8.6 本轮踩到的工具/环境陷阱（写脚本时必读，已同步进 `scripts/README.md`）

1. **多字节字节语义**：本机默认 `awk` 为 one-true-awk，`substr(s,1,1)` / `/^§[0-9]/` 按**字节**工作（`§`=2 字节、`：`=3 字节），用其判「第 1 个字符是不是 §」会**静默失配**并表现为"比对 0 个章节"的**假通过**。须用 `index()` + `length()` 推进字节。
2. **`$var` 紧跟中文标点**：非 UTF-8 locale 下 bash 会把后续多字节字节并入变量名（`$ttl」` → 变量 `ttl」`），配合 `set -u` 直接报「未绑定的变量」中断脚本。**凡变量与中文/全角标点相邻必须写 `${var}`**（本轮共修 8 处）。
3. **抽取中文文件名**：`grep -oE '[A-Za-z0-9_/.-]*\.md'` 匹配不到中文名，须改「非空白/反引号」字符类。
4. **awk 正则内 `/` 必须转义** `\/`，否则提前终止正则字面量。
5. **`" / "` 不是可靠的章节分隔符**：登记行存在「（业务）/ §2」这类**无前导空格**的写法，切分会漏章节；`§` 才是章节边界。
