# 项目长期约定（prototype-agent）

## 工程链路（核心定位）
本 agent 处于三阶段工程链路第一环：
`产品需求分析文件（需求包 01+02）` → `技术架构 agent 生成功能设计文件` → `编码 agent 生成代码`。

- 本 agent 产出 = **上游产品功能基础说明**，供技术架构 agent 作为下游输入。
- 职责边界：需求包只描述产品功能与业务行为（业务规则、功能边界、验收口径），**不设计技术方案**（数据模型、API、技术栈、字段级实现契约）——这些归下游技术架构 agent。
- Pencil 原型是可选视觉化辅助，非工程链路必需。

## 双段式工作流（必做/可选）
- 第一部分·需求分析（必做）：阶段1 业务架构 → 阶段2 逐页规格 → 产出并确认需求包。
- 决策门禁：需求包确认后才询问是否做原型（当前仅 Pencil，可插拔）。拒绝则产出 requirement-summary.md 结束。
- 第二部分·原型生成（可选）：调用 Pencil MCP 前须提示用户打开本地 Pencil 桌面应用 + 启动 Pencil MCP 服务。

## 关键约束
- 需求包工具无关：禁止写入 Pencil/绘图工具实现细节（页面命名、画布尺寸等）；页面中性序号用「页面[N]」，Pencil 命名 P{N}_/P{N}D{M}_ 由 pencil-executor 推导，不回写。
- 页面编号全工程统一为「页面[N]」（此前历史产物用「页面1」属旧式，不予参照）。

## 三层记录体系（结果态 / 操作流水 / 全貌索引）
把「当前态」与「历史」分离，由三类文件承担，互不污染：
- 工程级 `工程摘要.md`（索引式·轻，单文件原地更新）：工程下所有任务一行（任务目录 · 状态 · 一句话结论 · →链接任务结果摘要）。
- 任务结果级 `任务结果摘要.md`（独立文件·原地更新）：本任务状态封面，指向 01/02 与原型，不写进 01/02、不污染详细文档。
- 任务操作级 `任务操作记录.md`（单文件·只追加）：每条四字段——计划时间 / 执行内容 / 执行结果 / 复核结果；含需求侧（delivery 写）+ 原型侧（pencil-executor 写）。
- 旧版 `requirement-summary_{YYYYMMDD}.md` 按日版本化方案已废弃；日期仅作为操作记录条目时间戳，不进文件名。
- 刷新时机：01/02 或原型任一变动 → 刷新任务结果摘要 + 工程摘要；每次操作执行后 → 追加任务操作记录。

## 文档治理与单一权威源（2026-07-08 审计后确立）

全工程文档的「谁定义、谁引用」边界，避免多头重定义漂移：
- **决策门禁 / 工程项目归属判定**：判定逻辑唯一在 `CLAUDE.md`「调用与决策」；`AGENTS.md` 仅承载对话话术模板、`README.md`/`SETUP.md` 为概述，均不另立逻辑（CLAUDE 原「其他文件仅引用」声明已改为准确表述）。
- **原型端 Critical 约束**（Pencil 兼容性 / 单文件多页面 / 弹窗 / 视觉质量 / 启动前置）：权威源 = `skills/pencil-executor/SKILL.md`「Critical 级约束」；`CLAUDE.md` 仅作索引不展开；`agent/prototype-agent.md` 仅指向该 skill，不罗列。
- **阶段编号统一为「双段式」**：第一部分 = 阶段1 业务架构 / 阶段2 页面规格；第二部分 = 原型生成（具体操作 Step 1–8 在 pencil-executor）。已废弃「阶段3」「3a-3d」等旧编号；pencil-executor 标题由「阶段 3」改为「第二部分」。
- **02 页面模板**含「未决项」字段（每页），与 page-specs 完整性校验、任务结果摘要「未决项」节闭环。
- 术语对齐：工程摘要首列称「任务目录」；任务结果摘要引用 01 章节名用「角色与权限（产品级）」（非「矩阵」）。
