## A. 工程链路与双智能体

- 三阶段：`需求分析(prototype-agent) → 技术分析(architect-agent) → 编程(外部)`。
- **prototype-agent**：产出需求包（`系统要求规范` + `系统交互规范` + `modules/{模块}/01、02`）；**只写 prd/**。
- **architect-agent**：定位 = **需求翻译器/中转站，不做架构设计**；分层/选型/部署/非功能属**外部技术架构**、由**工程基线**（配置文件）承载，本项目不产出。**只写 tech/**（只读 prd/）。
- architect 模块级 = **三件套平级**（03 后端 / 04 数据 / 05 前端含移动端），**03 与 05 同轮产出**（共享同批 FR-x 与 operationId）；系统级 = 技术标准 / 技术规范 / 数据表设计约定 / 接口契约 / 代码工程结构说明。
- 指令文件：prototype = `CLAUDE.md` / `AGENTS.md`；architect = `CLAUDE.architect.md` / `AGENTS.architect.md`；注册入口 = `opencode.json`。

## B. 三层架构 + 四层统一模型

- **三层**：项目 `document/{项目名}/` → 系统 `{系统名}/`（无日期后缀）→ 模块 `prd/modules/{模块名}/`。
- **四层统一模型**（**FR-x 为唯一脊柱键**）：01 需求 = 场景[Sx]（业务情境·一级容器）→ 用户故事 / FR-x；02 UI = 页面[N] / 辅助页面[N-A] → 功能组件；03 技术 = 模块（技术域业务聚合，**非架构分层**）→ 功能点 FR-x；研发 = 代码模块 → 代码功能。
- 术语：02「功能组件」≠ 03「模块」≠ 研发「代码模块」；场景 ↔ 模块**多对多**（经 FR-x）。
- **02 弹窗二分**：复杂弹窗（创建/修改/配置类，独立表单+校验+提交）→ 独立辅助页面[N-A]（挂主页面、记所属场景）；简单弹窗（提醒/反馈/确认）→ 主页面内联一句话。
- FR-x 模块内从 FR-1 连续唯一；全局以「模块名+FR-x」定位（**不跨模块全局连续**）。

## S. 工具教训（必须遵守）

- 本环境 **Edit 存在「返回成功但内容未落盘」**现象。**大批量改动后必须用带 count 断言的脚本逐条 needle 复核**，失败则用 Python 直改兜底。
- **删改文件引用时必须把 frontmatter / description 纳入扫描**，且**断言脚本不能替代全仓裸 grep 交叉验证**。
- **写 / 改 shell 脚本（本环境特有陷阱）**：① 多字节需用 `index()` + `length()` 推进字节 —— one-true-awk 的 `substr(s,1,1)`、`/^§[0-9]/` 按**字节**工作，用于判「首字符是否 §」会**静默失配**；② `$var` 与中文/全角标点相邻**必须写 `${var}`** —— 非 UTF-8 locale 下 bash 会把标点字节并入变量名（`$ttl」` → 变量 `ttl」`），配合 `set -u` 直接报「未绑定的变量」中断；③ `grep -oE '[A-Za-z0-9_/.-]*\.md'` **匹配不到中文文件名**，须用「非空白/反引号」字符类；④ awk 正则内的 `/` 须转义为 `\/`；⑤ 校验脚本**必须对「抽不出条目」判失败**，否则表现为**假通过**（比对 0 条却报 ✅）。
- **章节分隔以 `§` 为准**，不可依赖 `" / "`：登记行存在「（业务）/ §2」这类无前导空格的写法，按 `" / "` 切分会**漏章节**。
