# 快速启动指南

本文档为新用户提供最简化的启动路径，5分钟快速上手。

## 最小启动步骤

### 1. 启动会话（首次使用）

```bash
# 1. 进入项目目录
cd /path/to/software-engineering-agent

# 2. 告诉 agent 你的需求（agent 会自动扫描工程、读取上下文）
# 示例：
"我要做一个任务管理系统，帮我梳理需求"
```

**Agent 会自动完成**：
- ✅ 扫描 `document/` 下所有工程
- ✅ 判断归属（新建工程 or 纳入已有工程）
- ✅ 读取工程级双文件（产品工程摘要.md + 产品通用规则.md）
- ✅ 复述已加载的约束（角色/权限/术语/UI标准）

### 2. 跟随对话流程

Agent 会按以下流程引导：

**阶段 1：业务架构沟通**（全局沟通）
- 回答关于端、功能类型、需求背景、用户、角色、业务场景的问题
- ✅ 确认门禁 1：业务基线确认

**阶段 2：逐页面详细沟通**（每页确认）
- 逐个页面讨论布局、功能组件、交互、状态
- ✅ 确认门禁 2：全部页面确认

**决策门禁**：需求包完成后选择后续环节
- ① 原型设计（可选）
- ② 技术分析（调用 architect-agent）
- ③ 结束（仅产出需求包）

### 3. 会话中断后恢复

```bash
# 1. 快速检查上下文
./scripts/context-recovery-check.sh

# 2. 如果检查失败，按提示执行：
"继续工作 {工程名} 下的 {任务名} 任务"
# Agent 会自动恢复上下文
```

## 目录结构一览

```
document/
└── {工程名}/                      ← 按业务归属划分
    ├── 产品工程摘要.md              ← 工程全貌（是什么+任务清单+维护记录）
    ├── 产品通用规则.md              ← 工程级标准（角色/权限/术语/UI标准）
    └── {任务名}_{YYYYMMDD}/        ← 任务子目录
        ├── prd/                    ← 产品产物（prototype-agent 产出）
        │   ├── 01-需求规格说明书.md
        │   ├── 02-UI交互规格说明书.md
        │   ├── prd-任务结果摘要.md    ← 状态封面（原地更新）

            ├── 03-技术规格说明书.md
            ├── 04-数据模型说明书.md
            ├── tech-任务结果摘要.md
            └── tech-任务操作记录.md
```

## 核心概念速查

### 四层统一模型（通过 FR-x 追溯）

| 层级 | 容器 | 原子单元 | 负责 Agent |
|------|------|----------|-----------|
| 01 需求规格 | 场景[Sx] | 功能点 FR-x | prototype-agent |
| 02 UI 交互 | 页面[N] | 功能组件 | prototype-agent |
| 03 技术规格 | 模块 | 功能点 FR-x | architect-agent |
| 研发实现 | 代码模块 | 代码功能 | 编程智能体 |

### 关键术语

- **场景[Sx]**：业务情境（如「新用户首单」），不是页面、不是技术模块
- **页面[N]**：主页面（完整功能页）
- **页面[N-A]**：辅助页面（复杂弹窗，有独立表单+校验+提交）
- **功能组件**：页面内的 UI 单元，承载一个 FR-x 的交互面
- **FR-x**：功能点编号，贯穿四层的追溯键

### 三层记录体系

1. **prd-任务结果摘要.md**：当前态封面，原地更新
2. **prd-任务操作记录.md**：历史流水，只追加
3. **产品工程摘要.md**：工程级索引，汇总所有任务

## 常见问题

**Q: 我可以跳过阶段 1 直接说页面需求吗？**
A: 不行。必须先完成阶段 1（业务架构）建立全局上下文，才能进入阶段 2（逐页面）。这是硬约束。

**Q: 需求包和原型是什么关系？**
A: 需求包（01+02）是必做产物，原型生成（Pencil）是可选的后续环节。需求包工具无关，可供任何下游消费。

**Q: 我可以修改已完成的任务吗？**
A: 可以。告诉 agent「维护 {任务名} 任务」，agent 会读取现有需求包作为修改基线。每次修改小版本号 +1。

**Q: 如何查看所有工程和任务？**
A: 查看 `document/` 目录，每个子目录是一个工程，每个工程的 `产品工程摘要.md` 列出了所有任务。

**Q: 技术分析（architect-agent）什么时候用？**
A: 需求包确认后，在决策门禁中选择「② 技术分析智能体」即可。它会基于 01-需求规格说明书.md 生成 03-技术规格说明书.md（模块+接口+伪代码）和 04-数据模型说明书.md。
