# 快速启动指南

本文档为新用户提供最简化的启动路径，5 分钟快速上手。

## 最小启动步骤

### 1. 启动会话（首次使用）

```bash
# 1. 进入项目目录
cd /path/to/software-engineering-agent

# 2. 告诉 agent 你的需求（agent 会自动扫描项目、读取上下文）
# 示例：
"我要做一个任务管理系统，帮我梳理需求"
```

**Agent 会自动完成**：
- ✅ 扫描 `document/` 下所有项目
- ✅ 判断归属（新建系统 or 纳入已有系统）
- ✅ 读取项目级文件（项目级产品摘要.md + 通用异常处理.md + 通用校验规则.md）
- ✅ 复述已加载的约束（角色/权限/术语/UI 标准）

### 2. 跟随对话流程

Agent 会按以下流程引导：

**阶段 1：系统架构沟通**（全局沟通）
- 回答关于系统定位、业务场景、角色、模块清单骨架、UI 风格的问题
- ✅ 确认门禁 1：系统架构基线确认

**阶段 2：逐模块详细沟通**（每模块确认）
- 逐个模块讨论功能要点（FR-x）、业务规则、页面布局、功能组件、交互、状态
- ✅ 确认门禁 2：全部模块确认

**决策门禁**：需求包完成后选择后续环节
- ① 原型设计（可选）
- ② 技术分析（调用 architect-agent）
- ③ 结束（仅产出需求包）

### 3. 会话中断后恢复

```bash
# 1. 快速检查上下文
./scripts/context-recovery-check.sh

# 2. 如果检查失败，按提示执行：
"继续工作 {项目名} 下的 {系统名}"
# Agent 会自动恢复上下文
```

        ├── prd/                      ← 产品产物（prototype-agent 产出）

        │   └── prd-系统操作记录.md      ← 操作流水（只追加）

## 核心概念速查

### 四层统一模型（通过 FR-x 追溯）

| 层级 | 容器 | 原子单元 | 负责 Agent |
|------|------|----------|-----------|
| 01 需求规格 | 场景[Sx] | 用户故事 / 功能点 FR-x | prototype-agent |
| 02 UI 交互 | 页面[N] | 功能组件 | prototype-agent |
| 03 技术规格 | 模块 | 功能点 FR-x | architect-agent |
| 研发实现 | 代码模块 | 代码功能 | 编程智能体 |

### 关键术语

- **场景[Sx]**：业务情境（如「新用户首单」），不是页面、不是技术模块
- **页面[N]**：主页面（完整功能页）
- **页面[N-A]**：辅助页面（复杂弹窗，有独立表单+校验+提交）
- **功能组件**：页面内的 UI 单元，承载一个 FR-x 的交互面
- **FR-x**：功能点编号，贯穿四层的追溯键；模块内从 FR-1 起编、连续唯一，全局以「模块名+FR-x」组合定位

### 三层记录体系

1. **prd-系统结果摘要.md**：当前态封面，原地更新
2. **prd-系统操作记录.md**：历史流水，只追加
3. **项目级产品摘要.md**：项目级索引，汇总所有系统

## 常见问题

**Q: 我可以跳过阶段 1 直接说页面需求吗？**
A: 不行。必须先完成阶段 1（系统架构）建立全局上下文，才能进入阶段 2（逐模块）。这是硬约束。

**Q: 需求包和原型是什么关系？**
A: 需求包（系统要求规范 + 模块 01/02）是必做产物，原型生成（Pencil）是可选的后续环节。需求包工具无关，可供任何下游消费。

**Q: 我可以修改已完成的系统吗？**
A: 可以。告诉 agent「维护 {系统名}」，agent 会读取现有需求包作为修改基线。每次修改小版本号 +1。

**Q: 如何查看所有项目和系统？**
A: 查看 `document/` 目录，每个子目录是一个项目，每个项目的 `项目级产品摘要.md` 列出了所有系统。

**Q: 技术分析（architect-agent）什么时候用？**
A: 需求包确认后，在决策门禁中选择「② 技术分析智能体」即可。它会基于模块 01 生成模块 03（模块+接口+伪代码）和 04（数据模型）。
