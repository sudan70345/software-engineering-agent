### P0 级 · 核心内容完善（必做，已全部完成）

#### 1. ✅ 上下文恢复检查点（CLAUDE.md）

**问题**: 长会话压缩后上下文丢失，agent 无法快速恢复。

**解决方案**:
- 在 `CLAUDE.md` 增加「上下文恢复检查点」章节（§上下文恢复检查点）
- 定义 R1-R4 四级检查项（工程名 → 双文件 → 任务上下文 → 会话快照）
- CLAUDE.architect.md 同步增加（技术侧场景）

**验证**:
```bash

```

**影响**: agent 在会话恢复时可按标准流程自检，减少上下文错误。

#### 4. ✅ 会话状态管理脚本

**问题**: 会话中断后无法快速恢复进度。

**解决方案**:
- 创建 `scripts/session-state.sh`（保存/列出快照）
- 创建 `scripts/context-recovery-check.sh`（自动化检查 R1-R4）
- 快照格式：`.session_state/snapshot_YYYYMMDD_HHMMSS.json`

**验证**:
```bash
ls -lh scripts/session-state.sh scripts/context-recovery-check.sh
./scripts/context-recovery-check.sh
```

**影响**: 
- 关键门禁点一键保存快照
- 恢复时自动检查上下文完整性，给出修复提示

---

#### 5. ✅ 文档一致性自动化校验

**问题**: 依赖 agent 自觉调用 self-check，无法保证每次执行。

**解决方案**:
- 创建 `scripts/validate-docs.sh`（7 项检查）
  - FR-x 编号连续性
  - 场景[Sx] 编号连续性
  - 页面[N] 与 §4 一致性
  - FR-x 的输入/输出/校验/异常完整性
  - 版本号一致性（01 与 02）
  - 职责边界（禁止接口定义/数据模型/技术选型）
- 创建 `scripts/pre-commit.sample`（Git hook）

**验证**:
```bash
# 手动校验
./scripts/validate-docs.sh --task-dir document/{工程名}/{任务名}_{YYYYMMDD}/

# 安装 pre-commit hook
cp scripts/pre-commit.sample .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

**影响**: 
- 提交前自动校验，阻止不完整文档入库
- CI pipeline 可集成，持续保障质量

## 五、使用建议

### 1. 立即启用的功能

```bash
# 1. 安装 pre-commit hook（一次性）
cp scripts/pre-commit.sample .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit

# 2. 在关键门禁点保存快照
./scripts/session-state.sh save

# 3. 会话恢复时自检
./scripts/context-recovery-check.sh
```

### 2. 新用户入门路径

1. 阅读 `docs/快速启动指南.md`（5 分钟）
2. 阅读 `docs/最佳实践.md` §需求沟通（10 分钟）
3. 开始第一个任务，agent 会自动引导

### 3. CI 集成建议

```yaml
# GitHub Actions / GitLab CI 示例
- name: Validate documents
  run: |
    ./scripts/validate-docs.sh --strict
```
