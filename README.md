# software-engineering-agent
这是一个多智能体协作项目，可以调用 “prototype-agent“ （需求分析智能体）自动分析用户产品需求，生成面向 AI 的结构化的需求分析文档，同时可以调用外部原型设计工具实现原型自动生成，或者调用“architect-agent“（技术分析智能体）分析指定生成的需求文档，生成面向编程智能体所需的技术设计文档。

## 工程链路与角色定义（全局权威）

本工程以「工程链路」组织三类智能体与产物，职责正交、单一权威源：

| 环 | 智能体（agent） | 角色 | 产出（存放） | 下游去向 |
|----|----------------|------|------------|---------|
| 第一环 | `prototype-agent` | 需求分析智能体 | 需求分析文档（即需求包 01/02，存于 `document/{工程名}/{任务名}_{YYYYMMDD}/prd/`） | → 技术分析智能体 阅读 |
| 第二环 | `architect-agent` | 技术分析智能体 | 技术分析文档（03 技术架构 / 04 数据模型 / 05 接口规划 / [+06 模块设计]，存于同任务 `tech/`） | → 编程智能体 消费 |
| 第三环 | 编程智能体（本工程暂未实现） | 编程 / 编码智能体 | 技术代码（由未来编程智能体依据 tech/ 产物生成） | — |

- **链路流向**：需求分析智能体生成需求分析文档（prd/）→ 作为输入供技术分析智能体阅读，生成技术分析文档（tech/）→ 再手动提供给编程智能体作为输入文档生成技术代码。
- **单一权威源**：prd/ 与 tech/ 通过任务根 `交接索引.md` 汇总，作为与编程智能体交接的清单；工程级规则与索引各自独立（`产品通用规则.md`/`产品工程摘要.md` 与 `技术通用规则.md`/`技术工程摘要.md`）。
- **原型生成为可插拔下游能力**：`prototype-agent` 在需求分析之外，可按用户选择调用 Pencil 生成原型（可选视觉化辅助），不改变其「需求分析智能体」的链路角色。
- **第三环说明**：编程智能体不在本工程实现；tech/ 产物（机器可读优先）即为其与未来编程智能体的输入契约。

## 运行流程简述（双段式）

1. **第一部分 · 需求分析（必做）**
   - 阶段 1：沟通业务架构，生成 `01-business-architecture.md` 并确认。
   - 阶段 2：逐页面沟通规格，生成 `02-page-specs.md` 并确认。
   - 两份文档合称「需求包」，仅描述产品功能与页面结构，不绑定任何绘图工具。

2. **决策门禁（需求包确认后触发）**（判定逻辑与结果处理详见 CLAUDE.md「调用与决策」）
   - 需求包确认后，agent 询问用户是否继续后续任务。
   - 当前仅提供「原型生成（Pencil 方案）」。
   - 用户拒绝 → 流程结束（任务结果摘要.md 已随需求包定稿生成、任务操作记录.md 已追加、产品工程摘要.md 已刷新）。
   - 用户同意 → 提示打开本地 Pencil 桌面应用并确保 Pencil MCP 服务已启动，进入第二部分。

3. **第二部分 · 原型生成（可选 · 当前绑定 Pencil）**
   - 仅在决策门禁中明确同意后调用 `skills/pencil-executor`。
   - 产出 `.pen`、截图、自校验报告、交付摘要。

4. **主要输出目录（工程项目 / 任务 两级）**
   - `document/{工程名}/{任务名}_{YYYYMMDD}/`
   - 工程级：`document/{工程名}/产品工程摘要.md`（全任务索引）、`document/{工程名}/产品通用规则.md`（跨任务共享，角色/权限/通用标准/术语）
   - 需求包（必出）：`01-business-architecture.md`、`02-page-specs.md`
   - 记录文件（必出）：`任务结果摘要.md`、`任务操作记录.md`
   - 原型包（可选）：`{task_name}.pen`、`pencil-execution-log.md`、`screenshots/`、`screenshots-reviewed/`、`validation-report.md`、`delivery-summary.md`、`ui-design-elements.md`

## 关键约束

- 工程项目归属：任务按业务归属归入 `document/{工程名}/`；同工程任务共享 `产品通用规则.md`，须读取、遵守并维护。
- 工程公共规则跨任务共享：角色定义、权限关联、通用业务规则、UI 标准与术语沉淀于 `document/{工程名}/产品通用规则.md`；收集过程中发现可通用规则须及时抽取进该文件。第二部分原型生成亦须遵循。
- 需求包工具无关：禁止写入 Pencil / 绘图工具的实现细节。
- 工程链路：需求分析智能体（prototype-agent）产出需求分析文档（需求包，上游产品功能基础说明）→ 技术分析智能体（architect-agent） 生成功能设计文件 → 编程智能体 生成代码。需求分析智能体不负责技术设计。
- 原型生成是可插拔方案：当前仅 Pencil；调用前必须提示用户打开本地 Pencil 桌面应用并启动 Pencil MCP 服务。
- 仅创建一个 `.pen` 文件；主页面和弹窗都应在同一文件内的独立 Pencil 页面中。
- 颜色必须使用 `#RRGGBB`，字体声明必须使用字符串字面量。
- 在进入原型生成前，必须先完成决策门禁，用户没有明确同意则不执行原型生成。

## 两个智能体（双 agent 共存）

本工程在同一仓库内同时承载两个可独立运行的 agent，共享 `document/{工程名}/` 资源与 skills 库，但产物数据各自独立存放：

| Agent | 角色 | 输入 | 输出目录 | 工程级规则 / 索引 |
|-------|------|------|---------|----------------|
| `prototype-agent`（需求分析智能体） | 需求分析 | 用户访谈 | `prd/`（01/02 + 原型） | `产品通用规则.md` / `产品工程摘要.md` |
| `architect-agent`（技术分析智能体） | 技术分析 | 需求分析文档（prd/01/02）或产品规划 md | `tech/`（03/04/05[+06]） | `技术通用规则.md` / `技术工程摘要.md` |

技术分析智能体（architect-agent）指令见 `CLAUDE.architect.md` 与 `AGENTS.architect.md`；技术产物经任务根 `交接索引.md` 汇总后交给编程智能体消费。
