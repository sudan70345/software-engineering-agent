# software-engineering-agent
这是一个多智能体协作项目，可以调用 “prototype-agent“ （需求分析智能体）自动分析用户产品需求，生成面向 AI 的结构化的需求分析文档，同时可以调用外部原型设计工具实现原型自动生成，或者调用“architect-agent“（技术分析智能体）分析指定生成的需求文档，生成面向编程智能体所需的技术设计文档。

## 工程链路与角色定义（全局权威）

本工程以「工程链路」组织三类智能体与产物，职责正交、单一权威源：

| 环 | 智能体（agent） | 角色 | 产出（存放） | 下游去向 |
|----|----------------|------|------------|---------|
| 第一环 | `prototype-agent` | 需求分析智能体 | 需求分析文档（即需求包：01-需求规格说明书.md + 02-UI交互规格说明书.md，存于 `document/{工程名}/{任务名}_{YYYYMMDD}/prd/`） | → 技术分析智能体 阅读 |
| 第二环 | `architect-agent` | 技术分析智能体 | 技术分析文档（03 技术规格说明书[模块→功能点两层] / 04 数据模型说明书，存于同任务 `tech/`） | → 编程智能体 消费 |
| 第三环 | 编程智能体（本工程暂未实现） | 编程 / 编码智能体 | 技术代码（由未来编程智能体依据 tech/ 产物生成） | — |

- **链路流向**：需求分析智能体生成需求分析文档（prd/）→ 作为输入供技术分析智能体阅读，生成技术分析文档（tech/）→ 再手动提供给编程智能体作为输入文档生成技术代码。
- **单一权威源**：prd/ 与 tech/ 通过任务根 `交接索引.md` 汇总，作为与编程智能体交接的清单；工程级规则与索引各自独立（`产品通用规则.md`/`产品工程摘要.md` 与 `技术通用规则.md`/`技术工程摘要.md`）。
- **原型生成为可插拔下游能力**：`prototype-agent` 在需求分析之外，可按用户选择调用 Pencil 生成原型（可选视觉化辅助），不改变其「需求分析智能体」的链路角色。
- **第三环说明**：编程智能体不在本工程实现；tech/ 产物（机器可读优先）即为其与未来编程智能体的输入契约。

## 设计亮点

### 门禁驱动 · 逐阶段确认再推进

两个智能体均采用「门禁」机制，每一阶段产出须经用户确认（门禁通过）才进入下一步，确保产出质量可控、可续跑：

- **prototype-agent**（需求分析）：阶段 1 业务架构 → 确认门禁 1；阶段 2 逐页面规格 → 确认门禁 2；需求包定稿后触发决策门禁（原型生成可插拔）。
- **architect-agent**（技术分析·需求翻译器 / 中转站）：阶段 0 技术通用规则确认（门禁 0）+ 阶段 1 需求解析（门禁 1，含模块初步归纳草案）+ 阶段 2 技术规格（门禁 2，**「模块 → 功能点」两层**：先按判据归纳模块脊柱，再逐功能点展开 9 子项——功能描述/输入/校验/处理逻辑/输出/异常/接口契约/接口初步规划(伪代码)/关联数据，不做架构设计）+ 阶段 3 业务表结构（门禁 3，六维确认含建表 DDL / 索引 DDL，实体按 03 模块分组派生）。确认后收口（门禁 4 同收口）。

### 多轮沟通 · 适配不同角色

- **prototype-agent**：访谈式递进沟通——从宏观业务架构（端、类型、角色、页面流转、UI 风格）逐步收敛到每页面微观规格（布局、模块、交互、状态与异常），适合产品需求从模糊到清晰的探索过程。
- **architect-agent**：解析 + 缺口确认式——先通读上游需求包（或独立产品规划 md），抽取业务场景/功能(FR-x)/角色/业务规则/非功能诉求，产出模块初步归纳草案，识别缺口与冲突后**精准反问**，不漫谈。技术通用规则缺失时（阶段 0），通过结构化问卷一次性确认技术语言、数据库、框架、并发基线、规范五类标准化信息。

### 数据独立 · 单一权威源

- **产物分层、互不污染**：同任务目录下，需求分析文档存入 `prd/`，技术设计文档存入 `tech/`。architect-agent 只读 prd/、只写 tech/，prototype-agent 不碰 tech/。
- **工程级规则双文件独立**：`产品通用规则.md`（产品侧维护，角色/权限/业务标准）与 `技术通用规则.md`（技术侧维护，框架/版本/规范/并发基线/错误码段）各自单一权威源。技术侧新增规则持续回写机制——全流程任何阶段出现新通用标准项即回写对应节并追加维护记录。技术分析智能体（architect-agent）不做架构设计，核心是需求翻译 + 模块归纳，以「模块 → 功能点」两层将需求翻译为 03-技术规格说明书（含接口契约 + 伪代码）+ 04-数据模型说明书，原接口规划/模块详细设计已并入 03。
- **三层记录体系**：任务级「结果摘要」（原地更新，当前态封面）+ 任务级「操作记录」（只追加，可复盘可续跑）+ 工程级「工程摘要」（索引式轻量全貌），产品侧与技术侧各维护独立副本。
- **交接索引为唯一交接清单**：任务根 `交接索引.md` 汇总 prd/ 与 tech/ 全部产物与状态，是向编程智能体交接的单一权威清单。

### 资源共享 · 同工程协同

- **同仓库、同资源**：两个智能体共享 `document/{工程名}/` 数据目录与 `skills/` 技能库，同一任务目录（`{任务名}_{YYYYMMDD}`）为共享锚点。
- **各自独立可运行**：每个智能体有独立的指令文件（`CLAUDE.md`/`AGENTS.md` vs `CLAUDE.architect.md`/`AGENTS.architect.md`）和 opencode 注册，互不干扰。
