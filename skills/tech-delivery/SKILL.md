# 技术系统结果摘要 Skill

## 🛡️ 执行前自检（必做）

执行本 Skill 前必须确认：
1. ✅ 已读取项目级技术摘要.md + 系统级技术标准/规范
2. ✅ 当前项目名与系统目录明确
3. ✅ 本 Skill 产出文件归属正确（tech/ 子目录）
4. ✅ 已读取所有**模块级** 03-*.md 和 04-*.md 文件、系统级标准/规范文件、系统总览和依赖清单

**若任一项不确定 → 立即执行「CLAUDE.architect.md §上下文恢复检查点」R1-R4 流程。**

---

## 定位
本 Skill 在「技术设计文档（03/04）被新建或修改后的任意时刻」被调用，生成/原地更新技术系统结果摘要，并维护技术分析智能体（architect-agent）记录体系 + 交接索引。
- 与需求分析智能体（prototype-agent） `delivery` Skill **完全独立**：文件位于 `tech/` 子目录、项目级索引为 `项目级技术摘要.md`、系统级交接索引 `交接索引.md` 在系统根目录。
- 产物供下游「编程智能体」作为输入；编程智能体读取本系统 `tech/` 子目录即可获得全部技术设计。

## 触发条件
- 03/04 全部确认后，生成初始摘要；
- 任一技术文档被修改并提交后，刷新摘要。

## 输入
- `tech/modules/*/03-*.md`（所有模块的技术规格）
- `tech/modules/*/04-*.md`（所有模块的数据模型）
- `tech/系统级技术标准.md` + `tech/系统级技术规范.md`（系统级标准与目标）
- `tech/数据表设计约定.md`（数据表设计规范）
- `tech/模块间接口依赖清单.md`（模块间依赖）
- `tech/tech-系统操作记录.md`（技术操作记录）
- `../prd/prd-系统结果摘要.md`（上游产品结果摘要，可选参考）

## 输出

### 1. tech/tech-系统结果摘要.md（单文件·原地更新）
- 路径：`document/{项目名}/{system_dir}/tech/tech-系统结果摘要.md`
- 结构以 `templates/architect-agent/system-level/tech-系统结果摘要.md` 为权威源；首次复制填充占位符，后续原地更新同一文件。

### 2. tech/tech-系统操作记录.md（单文件·只追加）
- 路径：`document/{项目名}/{system_dir}/tech/tech-系统操作记录.md`
- 若文件不存在则复制 `templates/architect-agent/system-level/tech-系统操作记录.md` 表头后追加一条技术分析智能体（architect-agent）条目（四字段）。

### 3. 项目级技术摘要.md（项目级·原地更新）
- 路径：`document/{项目名}/项目级技术摘要.md`
- 结构以 `templates/architect-agent/project-level/项目级技术摘要.md` 为权威源
- **首次创建**：若文件不存在，从模板复制并填充占位符（`{项目名}`），§0（项目概览）部分应已在项目初始化时填充（见 CLAUDE.architect.md §调用与决策·新建项目时的初始化）
- **原地更新**：若文件已存在，刷新/新增本系统行（系统目录 · 当前状态 · 一句话结论 · 技术设计产物 · →链接），并追加 §2 维护记录

### 4. 交接索引.md（系统级·确保存在并最新）
- 路径：`document/{项目名}/{system_dir}/交接索引.md`
- 结构以 `templates/交接索引.md` 为权威源；汇总 prd/ 与 tech/ 产物路径与状态，作为编程智能体交接清单。若系统根目录已有需求分析智能体（prototype-agent）创建的 `交接索引.md`，原地更新 tech 部分即可。

## 边界
- **分层精简**：系统级文件（系统级技术标准.md、系统级技术规范.md、数据表设计约定.md、依赖清单.md）的生成由各阶段 skill 负责，本 skill 仅聚合统计
- **不创建编程代码**：仅生成技术规范文档，交接清单；代码由编程智能体负责

### Step 1：读取与统计

遍历所有**模块级文件**和**系统级文件**，统计：
- 模块数量（m）
- 接口总数（i）
- 数据表总数（t）
- 关键流程数、并发保护策略数
- 功能点完整性（FR-x 对应 TFP-x 覆盖率）
- 异常定义完整性（错误码覆盖）
- 索引映射表完整性（查询场景→索引）
- 并发约束明确性（行级锁/事务/唯一约束等）

### Step 2：生成 tech-系统结果摘要.md

基于模块级和系统级文件的内容，生成/更新 `tech/tech-系统结果摘要.md`，包含：
- 系统状态、版本、模块数/接口数/表数等指标
- 技术设计产物清单（各模块 03/04 + 系统文件）
- 模块设计概览（每个模块的功能点数、表数、关键技术）
- 核心设计亮点总结
- 数据一致性与并发保护总结
- 交接准备说明

模板见 `templates/architect-agent/system-level/tech-系统结果摘要.md`

### Step 3：更新 tech-系统操作记录.md

向 `tech/tech-系统操作记录.md` 追加收口条目（四字段）：
- 计划时间：本次收口时间
- 执行内容：汇总技术分析结果
- 执行结果：生成的文件清单
- 复核结果：一致

### Step 4：刷新项目级 项目级技术摘要.md

更新 `document/{项目名}/项目级技术摘要.md`：
- 系统清单行：更新该系统的状态、版本、产物链接
- 维护记录：追加本次技术分析的记录行（时间/系统目录/变更范围/版本）

### Step 5：交接索引.md（系统级·确保存在并最新）
- 路径：`document/{项目名}/{system_dir}/交接索引.md`
- 结构以 `templates/交接索引.md` 为权威源
- 汇总 prd/ 与 tech/ 产物路径与状态，作为编程智能体交接清单
- 若系统根目录已有需求分析智能体（prototype-agent）创建的 `交接索引.md`，原地更新 tech 部分即可
