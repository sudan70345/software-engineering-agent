# 技术规格说明书 Skill — 阶段 2（枢纽 / 中转站）

> 📌 **权威源引用**：术语定义见 `CLAUDE.architect.md §术语对照表`；文档结构见 `templates/03-技术规格说明书.md`（单一权威模板）；确认话术见 `AGENTS.architect.md §阶段 2`。

## 定位
本阶段是 architect-agent 的**核心枢纽**：把上游需求包（01 的 FR-x）**归纳为模块**并翻译为可直接指导编码的技术规格（模块 → 功能点两层）。**不做架构设计**——技术选型/分层/部署/非功能等架构约束全部来自 `../技术通用规则.md`（工程级单一权威源），本阶段只引用。
- ⚠️ **模块归纳 ≠ 架构设计**：把扁平 FR-x 按统一业务逻辑聚合为模块，是「需求翻译」的核心（允许、必做）；决定 service/dao 分层、技术选型、部署拓扑才是架构设计（不做，归 `../技术通用规则.md` / 研发）。
- ⚠️ **模块 ≠ 场景**：01 的场景是业务情境（横切叙事、跨模块）；模块是技术域聚合（围绕核心业务对象的功能簇）。二者经 FR-x 多对多关联，勿把场景当模块。
- ⚠️ **本阶段产出为初步分解**（偏细、可审阅）：架构受限下**宁细勿粗**，最终合并/映射代码模块由后续人员/研发结合真实架构决定，本阶段不越界替其决策。

## 工作流程

### Step 1：归纳模块脊柱（§1 模块划分总览）
读取 `../prd/01-需求规格说明书.md` §7 全部 FR-x，按**模块归纳判据**聚合为模块，产出「模块 → FR-x」映射（§1.2 总览表：模块/名称/类型/覆盖能力/含FR-x/待校准）。**每条 FR-x 必须且仅归属一个主模块**，跨模块调用在功能点「关联模块」中记录，不重复归属。禁止遗漏或重复 FR-x（与 01 双向可追溯）。
- **模块归纳判据**（写入 §1.1）：① 主对象归属（FR-x 服务的核心业务对象/能力）；② 同对象聚合为业务域模块（覆盖对象完整 CRUD 生命周期）；③ 跨切面能力独立成模块（鉴权/通知/日志等，被多模块共享且独立演进）；④ 跨对象功能按核心能力归属，调用他模块记为「关联模块」；⑤ 粒度**宁细勿粗**，拿不准就单独成模块。
- **模块类型**：业务域 / 跨切面。

### Step 2：逐模块 → 逐功能点展开（§2 核心）
按模块（M1、M2…）逐个展开；每个模块块 = **模块定义/边界段** + 其下若干**功能点块**。

> ⚠️ **生成中遇不确定必须暂停反问（硬规则）**：写功能点 ④ 处理逻辑（复杂逻辑 / 状态机 / 算法）等时，若业务规则不清、存在多种合理实现、或信息与上游 01/02 及「技术通用规则.md」冲突，必须**立即停止并向用户确认后再落笔**；禁止臆造、禁止仅以「待确认」标记直接出稿等门禁 2 时再发现。确认过程记入 `tech/tech-任务操作记录.md`，必要时登记 TECH-OPEN-*。

- **模块定义/边界段**：核心业务对象/能力 · 统一业务逻辑（内聚点）· 聚合的 FR-x · 关联场景（经 FR-x，来自 01 §2.4）· 关联模块（跨模块调用）· 边界说明（本模块不含什么）。
- **功能点块**（= FR-x）：按 `templates/03-技术规格说明书.md` 的 9 子项结构展开（功能描述/输入/校验/处理逻辑/输出/异常/接口契约/伪代码/关联数据）。
  > ⚠️ ⑦接口契约（机器可读）与⑧伪代码（可译性）须并存，详见模板注释。

### Step 3：错误码表（§3）
汇总本任务分段错误码；通用分段规则引用 `../技术通用规则.md` §5（统一约定：响应结构 / 错误码分段 / 鉴权 / 分页 / 软删 / 审计 / 幂等）。

### Step 4：技术风险与待确认（§4）
登记 TECH-OPEN-*；上游 OPEN-* 承接（仅记录技术侧依赖）。

### Step 5：写出 03 并展示确认（门禁2）
按 `templates/03-技术规格说明书.md` 落地 `tech/03-技术规格说明书.md`，展示摘要（模块数及类型分布 / FR 覆盖数 / 接口数 / 错误码数 / 技术风险 / 待校准模块数），确认门禁2。
- 用户修改 → 更新，重确认。
- 确认 → 进入 data-model（阶段 3）。

### Step 6：记录
向 `tech/tech-任务操作记录.md` 追加阶段 2 条目（四字段）。

## 边界
- **不设计架构**：技术选型/分层/部署/非功能一律引用 `../技术通用规则.md`，不在 03 展开；若发现新通用标准项，回写 `../技术通用规则.md` 对应节（架构基线→§7/§8/§9、规范→§4/§5、并发→§1）并追加 §10 维护记录。
- **模块归纳属需求翻译**：把 FR-x 聚合为模块（业务域/跨切面）是本阶段核心职责；但**不决定**模块内部分层与技术实现（归研发）。
- **接口契约内联**：接口不再独立成文档（原 05 已并入功能点子项7），保证「功能→接口」同处可查。
- **复杂逻辑内联**：复杂模块设计不再独立成文档（原 06 已并入功能点「处理逻辑」子项4）。
- **模块 ≠ 场景 ≠ 代码模块**：03 模块是技术域聚合；01 场景是业务情境；研发代码模块由 03 模块近 1:1 翻译得出，但最终边界由研发定。
