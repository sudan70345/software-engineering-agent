# 接口规划 Skill — 阶段 4

## 输入
- `tech/03-tech-architecture.md`、`tech/04-data-model.md`（已确认）
- `../prd/02-page-specs.md`（产品页面清单，作为接口按页面分组的来源）
- `../技术通用规则.md`（响应结构/错误码/鉴权/分页约定）

## 前置条件
- data-model 门禁3 已通过

## 输出
- `tech/05-api-design.md`（结构见 `templates/api-design.md`）
- 可选：OpenAPI 3.0 片段（供编程智能体直接消费）

## 工作流程

### Step 1：按页面维度分组
读取 `../prd/02-page-specs.md` 的页面清单，将每个页面的功能需求映射为该页面的「计划接口需求」；以**页面**为第一分组维度（资源组作为页面内归类参考），列出接口总览。

### Step 2：逐接口定义（含异常处置与并发需求）
每个接口须给出：方法/路径/鉴权/请求 schema（输入）/响应 schema（输出）/状态码/分段错误码/**异常处置**（各异常的 HTTP/code/message/触发场景/处置动作）/ **并发情况需求**（并发场景、幂等键、峰值 QPS、锁策略）。机器可读优先（字段类型明确、约束清晰）。

**并发需求分层**：先读取 `../技术通用规则.md` §1.5 项目整体并发基线（峰值 QPS / 数据量级 / 一致性 / 延迟等），以此为各接口默认并发假设；然后**逐接口询问用户**该接口是否存在超出基线的特殊高并发场景（特殊的并发行为、额外幂等键、专用锁策略、限流要求等），若有则单独写入该接口的「并发情况需求」中；无特殊情况则注明"与项目基线一致（见技术通用规则 §1.5）"。

### Step 3：错误码表与通用约定
汇总本任务错误码（分段），引用 技术通用规则 第 5 节通用约定（响应结构/鉴权/分页）。

### Step 4：写出 05 并确认（门禁4 · 按页面维度）
按页面展示：每个页面 → 计划接口需求 → 逐接口 输入/输出/异常处置/并发情况需求；并附错误码分段。请操作人员**逐页逐接口**确认（页面/计划接口/输入/输出/异常处置/并发需求）无误后回复「确认」，再进入 module-design（阶段 5，可选）或直接 tech-delivery。

### Step 5：记录
追加 `tech/任务操作记录.md` 阶段 4 条目。
