# 逐页沟通 Skill — 阶段 2（第一部分 · 需求分析）

## 输入

- `document/{工程名}/{task_dir}/prd/01-business-architecture.md`（已确认）
- `document/{工程名}/产品通用规则.md`（所属工程的公共规则，须先读取并遵守）

## 前置条件

- 业务架构文档已通过用户确认
- 已读取所属工程 `产品通用规则.md`，复用其中角色 / 权限 / 通用标准与术语

## 输出

- `document/{工程名}/{task_dir}/prd/02-page-specs.md`（累积追加写入）

> ⚠️ **工具无关**：本文件只描述产品功能与页面结构，禁止写入 Pencil / 绘图工具的实现细节（如 Pencil 页面命名、画布尺寸等）。页面/弹窗的绘制命名将在第二部分（若启用原型生成）由 pencil-executor 从本文推导。
> ⚠️ **职责边界**：本文件描述**产品功能与业务行为**，不设计技术方案（数据模型、API、技术栈、字段级实现契约归下游技术分析智能体（architect-agent））。尺寸类描述写产品意图而非实现像素。

---

## 内容分工约定（避免重复，单一权威源）

为让下游（技术分析智能体（architect-agent））拿到无歧义的输入，三处内容须明确分工、不重复：

- **模块清单**：页面的结构块（functional area）。每个模块写清「类型 / 内容 / 自身直接行为 / 可见角色」。模块自身的局部交互（如点击展开、输入）在此描述即可。
- **关键元素**：仅用于强调**单个关键控件**（如核心 CTA、特殊输入），且该控件**不应已作为模块出现**。避免把模块清单里已有的元素再列一遍。
- **交互定义表**：**仅记录跨页导航与全局反馈**（如跳转到某页、全局 Toast）。模块内的局部交互不要在此重复。

> 若同一交互在多处出现，以「模块清单」为准，关键元素与交互定义表只做引用、不重述细节。

## 工作流程

### Step 1：读取业务架构文档中的页面清单

从 `01-business-architecture.md` 中提取页面清单（编号「页面[N]」），确认沟通顺序（通常按页面流转顺序，从首页开始）。

> 📌 同时读取所属工程的 `产品通用规则.md`：复用其中**通用角色定义、权限关联、通用模块与术语**，沟通中直接引用，避免重复定义；本任务特有的角色差异/模块才在 02 中展开。

> ⚠️ **新页面回写 01**：若逐页沟通中发现 01 未列出的页面（如设置页），须同步更新 `01-business-architecture.md` 的「页面拆解」与「页面流转」，保持 01/02 一致。

### Step 2：逐页面沟通

对每个核心页面按以下顺序逐一与用户对话：

#### 2a. 结构布局
```
「{页面名称} 页面的整体布局是什么样？
 - 上下结构 / 左右分栏 / 卡片流 / 列表 / 网格 / 混合
 - 是否有固定顶部导航栏、底部 Tab Bar、侧边栏？」
```

#### 2b. 模块内容
```
「页面包含哪些功能模块？
 哪些是重要的核心模块？
 哪些是次要/辅助模块？
 哪些是不应该出现的内容？
 各模块面向哪些角色（可见性差异）？」
```

#### 2c. 关键元素与交互
```
「页面中最重要的交互元素是什么？
 需要引入哪些标准页面功能组件？（如搜索、筛选、分页、表单、列表、图表、树形、浮层等）
 是否有弹窗、浮层、子页面等交互形式？
 用户的操作行为有哪些？（点击、滑动、输入、长按…）」
```

#### 2d. 状态与异常
```
「这个页面有哪些典型状态？
 - 空态：列表/数据为空时显示什么？
 - 加载中：数据请求时的表现？
 - 错误态：加载/提交失败时的提示？
 - 受限态：无权限或条件不满足时显示什么？」
```

#### 2e. 业务规则与传参
```
「页面涉及哪些产品业务规则？（如：商品下架后不可下单、删除需二次确认）
 从其他页面进入本页时，需要携带什么参数？（如商品ID、筛选条件）」
```

#### 2f. 写入设计描述

每页沟通确认后，将其描述追加到 `02-page-specs.md` 中：

```markdown

- 整体布局: [布局类型]

2. **[模块2名称]**（ID: 页面[N]-M2）
   - ...

#### 🟡 次要模块
1. **[模块N名称]**（ID: 页面[N]-Mk）
   - ...

### 关键元素（仅强调的单控件，不与模块重复）
- [元素1]: [描述，如: 搜索输入框，固定顶部，宽度占满]
```

> 📌 **通用模块 / 标准抽取（必做）**：逐页沟通中，若发现某模块、交互模式、状态表现或术语在工程中多个任务通用，将其抽取进 `产品通用规则.md`（如「通用模块清单」「通用术语表」），02 内改为引用，保持单一权威源。已有工程任务须同步增量维护该文件。

- [ ] 每个页面均定义了「页面状态」（空/加载/错误/受限）；
