从 `02-UI交互规格说明书.md` 的 §3「页面总览」提取「页面[N]」清单，确认沟通顺序（通常按页面流转顺序，从首页开始）。

### Step 2：逐页面沟通（双向落档）

对每个页面[N] 按以下顺序逐一与用户对话，**同一轮对话同时产出 02 与 01 内容**：

#### 2a. 结构布局（→ 02 §4）
```
「{页面名称} 页面的整体布局是什么样？
 - 上下结构 / 左右分栏 / 卡片流 / 列表 / 网格 / 混合
 - 是否有固定顶部导航栏、底部 Tab Bar、侧边栏？」
```

#### 2b. 功能组件内容（→ 02 §4）
```
「页面包含哪些功能组件？（每个组件对应一个 FR-x）
 哪些是重要的核心组件？
 哪些是次要/辅助组件？
 哪些是不应该出现的内容？
 各组件面向哪些角色（可见性差异）？」
```
> ⚠️ 术语：页面内 UI 单元统一称「功能组件」（非「功能模块」）；「模块」专属下游 03。

#### 2c. 关键元素与交互（→ 02 §4）
```
「页面中最重要的交互元素是什么？
 需要引入哪些标准页面功能组件？（如搜索、筛选、分页、表单、列表、图表、树形、浮层等）
 是否有弹窗、浮层、子页面等交互形式？
   → 复杂弹窗（有独立表单+校验+提交，如创建/修改/配置）：提升为独立辅助页面 页面[N-A]，单列子节规格化，记「所属主页面」；
   → 简单弹窗（操作提醒/结果反馈/确认框，无独立业务处理）：在本页内联一句话描述，不单列。
 用户的操作行为有哪些？（点击、滑动、输入、长按…）」
```

#### 2d. 状态与异常（→ 02 §4 页面状态变体）
```
「这个页面有哪些典型状态？
 - 空态：列表/数据为空时显示什么？
 - 加载中：数据请求时的表现？
 - 错误态：加载/提交失败时的提示？
 - 受限态：无权限或条件不满足时显示什么？」
```

#### 2e. 功能与业务规则（→ 01 §6 用户故事 / §7 功能要点 / §8 业务实体 / §9 业务规则）
```
「这个页面要交付哪些功能能力？（逐条提炼为功能点 FR-x，定优先级 P0/P1/P2）
 每个功能属于 §2.4 的哪个业务场景？（回填「所属场景」场景[Sx]，一条功能可属多个场景）→ 同步回填 §2.4 场景的「涉及 FR-x / 页面[N]」
 本页涉及哪些业务实体 / 对象？其业务属性有哪些（用业务语言，如优惠券的「面额 / 使用门槛」）？→ 记入 01 §8 业务实体
 页面涉及哪些产品业务规则？（如：商品下架后不可下单、删除需二次确认）
   → 复杂规则（金额/时效/并发/幂等）须追问：触发条件？判定分几步？不满足时给什么业务输出？有无降级或边界（如实付<0归0）？
     严禁把事务回滚/幂等键/锁机制等技术实现写进 §9。
 作为<角色>，我希望<能力>，以便<价值>。（绑定功能的用户故事）
   → 追问验收：成功时怎样？典型失败时怎样？边界态（超时/并发/临界值）怎样？」
```

#### 2f. 输入 / 输出 / 校验 / 异常（→ 01 §10/§11/§12/§13）
```
「这些功能分别需要哪些输入字段？（字段名 / 类型 / 来源 / 是否必填 / 默认值 / 约束）
   → 若某字段是列表且每项含子字段（如商品清单→商品ID/规格/数量），用「子项 each_item」结构逐级展开
 操作成功 / 失败时系统各输出什么？（展示数据 / 系统响应 / 副作用；失败态记「哪种失败→给哪类提示语义」，提示的视觉呈现方式归 02）
 每个字段的校验规则？（必填 / 格式 / 范围 / 唯一）
 异常场景与处理？强制穷举：并发竞争 / 外部降级超时 / 重复提交幂等 / 数据中途失效 / 权限中途变化
   → 每类异常追问：发生时机？系统侧怎么处置？用户看到什么提示语义？如何恢复（自动重试/手动重试/返回上一步）？」
```

#### 2g. 页面流转与传参（→ 02 §4 页面流转）
```
「从其他页面进入本页需携带什么参数？（如商品ID、筛选条件）
 本页操作后跳转到哪里？携带什么参数回来？」
```
