# 任务结果摘要 Skill（基于 01-需求规格说明书 + 02-UI交互规格说明书）

## 🛡️ 执行前自检（必做）

执行本 Skill 前必须确认：
1. ✅ 已读取工程级双文件（产品工程摘要.md + 产品通用规则.md）
2. ✅ 当前工程名与任务目录明确
3. ✅ 本 Skill 产出文件归属正确（prd/ 子目录）
4. ✅ 已读取任务的 01-需求规格说明书.md 和 02-UI交互规格说明书.md

**若任一项不确定 → 立即执行「CLAUDE.md §上下文恢复检查点」R1-R4 流程。**

---

## 定位

本 Skill 在「需求包（01-需求规格说明书.md + 02-UI交互规格说明书.md）」被**新建或修改后的任意时刻**被调用，生成 / 原地更新**任务结果摘要**，并同步维护跨文件记录体系。

- **与 Pencil 原型生成完全无关**：不依赖、不引用、不等待任何 Pencil 调用或产物；Pencil 的交付由 `pencil-executor` Skill 自有负责。
- 本 Skill 的产物是需求分析阶段（第一部分）的收口交付物，也是 01 / 02 任何变更的**同步产物**，供下游技术架构 Agent 作为输入。
- **记录体系职责（本 Skill 承担需求侧）**：
  1. 生成 / 更新 `prd-任务结果摘要.md`（独立文件、无日期后缀、原地更新）；
  2. 向 `prd-任务操作记录.md` 追加一条需求侧操作条目（四字段）；
  3. 刷新工程级 `产品工程摘要.md` 的对应任务行（索引式）。

## 触发条件

满足以下任一即应触发（或提醒触发）：

- 阶段 2 全部页面确认（01-需求规格说明书.md + 02-UI交互规格说明书.md 定稿）后，生成初始摘要（首次新建，文档版本保持 v1.0）；
- 01 或 02 被修改（补充页面、调整规则、抽取公共规则、维护更新等）并提交后，刷新摘要，且**小版本号 +1**（见下方版本规则）。

> 触发本质是「01 / 02 文件发生变化」，而非「是否生成原型」。

### 小版本号规则（01/02 每次更新/优化）

- 首次新建并定稿：两份文档 `文档版本` = v1.0。
- 后续每次「更新 / 优化」提交：两份文档 `文档版本` **小版本号 +1**（v1.0 → v1.1 → v1.2 …）；仅当需求包结构性重构时大版本号 +1（v1.x → v2.0）。
- 版本变更须同步：在 `prd-任务操作记录.md` 追加条目标注**本版本号**与**本次变更范围**（如「v1.1：补充页面[3] 导出功能 + 修订 BR-4 判定逻辑」）；并在 `prd-任务结果摘要.md` 反映最新版本。
- 维护场景下若检测到 `tech/` 已存在：提醒用户是否调用技术分析智能体对齐更新；architect 更新后其 tech 文档（03/04）小版本号同步 +1（对齐 prototype-agent 联动，详见 CLAUDE.architect.md）。

## 输出

- 路径：`document/{工程名}/{task_dir}/prd/prd-任务结果摘要.md`
- **无日期后缀、原地更新**：始终为最新结果态；历史变更由 `prd-任务操作记录.md` 承载，本文件不堆叠版本。

### 2. prd-任务操作记录.md（单文件 · 只追加）
- 路径：`document/{工程名}/{task_dir}/prd/prd-任务操作记录.md`
- 若文件不存在则创建并写入表头；否则仅在末尾追加一条需求侧条目（四字段）。

### 3. 产品工程摘要.md（工程级 · 原地更新）
- 路径：`document/{工程名}/产品工程摘要.md`
- 刷新 / 新增本任务对应的索引行（见下文格式）。

## 工作流程

### Step 1：读取与统计
读取最新 01 / 02 与工程公共规则（若为更新场景，两份文档 `文档版本` 应已按小版本号规则 +1），统计页面 / 弹窗 / 角色 / 功能点(FR) / 未决项，生成 `prd-任务结果摘要.md`（结构以 `templates/prd-任务结果摘要.md` 为单一权威源）。

### Step 2：写入 / 更新 prd-任务结果摘要.md

> 结构以 `templates/prd-任务结果摘要.md` 为单一权威源。**首次创建时从模板复制**并填充占位符（`{任务名称}` / `{工程名}`）；后续原地更新同一文件，不新建版本。
>
> ⚠️ 本 Skill **不内联模板内容**：完整骨架以 `templates/prd-任务结果摘要.md` 为准，避免与模板漂移。

### Step 3：向 prd-任务操作记录.md 追加需求侧条目

> 结构以 `templates/prd-任务操作记录.md` 为单一权威源。**首次创建时从模板复制**并填充 `{任务名称}` 占位符作为表头与首条；后续仅追加条目，不修改历史。
>
> ⚠️ 本 Skill **不内联模板内容**：完整表头以 `templates/prd-任务操作记录.md` 为准。
> 每条需求侧条目含四字段：计划时间 / 执行内容 / 执行结果 / 复核结果。

### Step 4：刷新 产品工程摘要.md（工程全貌）

> 结构以 `templates/产品工程摘要.md` 为单一权威源（§0 工程概览 / §1 任务清单 / §2 工程维护记录）。**首次创建时从模板复制**并填充 `{工程名}` / `{task_dir}` 占位符；后续原地更新对应任务行、追加维护记录，不新建版本。
打开 `document/{工程名}/产品工程摘要.md`：
- 不存在 → 从模板创建并填充：
  - **§0 工程概览**：`工程名` 取 `{工程名}`；`业务领域 / 范围` 与 `一句话定位` 从本任务 `01-需求规格说明书.md` §2 需求背景与功能概述提炼（新建工程时即记录，避免基本信息散落到通用规则）。
  - **§1 任务清单**：写入本任务行（任务目录 · 当前状态 · 一句话结论（任务是什么） · →链接）。
  - **§2 工程维护记录**：追加首条（时间 / 任务目录 / 变更类型「新建」/ 版本，取 01 当前 `文档版本`）。
- 已存在 → 更新 / 新增 §1 本任务行（任务目录 · 当前状态 · 一句话结论 · 链接）；并在 §2 **追加一条维护记录**（时间 / 任务目录 / 变更类型「修订 {范围}」/ 版本，取 01 最新 `文档版本`），呈现工程已做成的全貌。
