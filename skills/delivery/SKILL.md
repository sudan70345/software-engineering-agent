# 任务结果摘要 Skill（基于 01 / 02）

## 定位

本 Skill 在「需求包（01-business-architecture.md + 02-page-specs.md）」被**新建或修改后的任意时刻**被调用，生成 / 原地更新**任务结果摘要**，并同步维护跨文件记录体系。

- **与 Pencil 原型生成完全无关**：不依赖、不引用、不等待任何 Pencil 调用或产物；Pencil 的交付由 `pencil-executor` Skill 自有负责。
- 本 Skill 的产物是需求分析阶段（第一部分）的收口交付物，也是 01 / 02 任何变更的**同步产物**，供下游技术架构 Agent 作为输入。
- **记录体系职责（本 Skill 承担需求侧）**：
  1. 生成 / 更新 `任务结果摘要.md`（独立文件、无日期后缀、原地更新）；
  2. 向 `任务操作记录.md` 追加一条需求侧操作条目（四字段）；
  3. 刷新工程级 `产品工程摘要.md` 的对应任务行（索引式）。

## 触发条件

满足以下任一即应触发（或提醒触发）：

- 阶段 2 全部页面确认（02 定稿）后，生成初始摘要；
- 01 或 02 被修改（补充页面、调整规则、抽取公共规则等）并提交后，刷新摘要。

> 触发本质是「01 / 02 文件发生变化」，而非「是否生成原型」。

## 输入

- `document/{工程名}/{task_dir}/prd/01-business-architecture.md`（最新，已确认）
- `document/{工程名}/{task_dir}/prd/02-page-specs.md`（最新，已确认）
- `document/{工程名}/产品通用规则.md`（工程级公共规则，已读取并维护）

## 输出

### 1. 任务结果摘要.md（单文件 · 原地更新）
- 路径：`document/{工程名}/{task_dir}/prd/任务结果摘要.md`
- **无日期后缀、原地更新**：始终为最新结果态；历史变更由 `任务操作记录.md` 承载，本文件不堆叠版本。

### 2. 任务操作记录.md（单文件 · 只追加）
- 路径：`document/{工程名}/{task_dir}/prd/任务操作记录.md`
- 若文件不存在则创建并写入表头；否则仅在末尾追加一条需求侧条目（四字段）。

### 3. 产品工程摘要.md（工程级 · 原地更新）
- 路径：`document/{工程名}/产品工程摘要.md`
- 刷新 / 新增本任务对应的索引行（见下文格式）。

## 工作流程

### Step 1：读取与统计
读取最新 01 / 02 与工程公共规则，统计页面 / 弹窗 / 角色 / 未决项，生成 `任务结果摘要.md`（完整覆盖下方模板）。

### Step 2：写入 / 更新 任务结果摘要.md

> 结构以 `templates/任务结果摘要.md` 为单一权威源。**首次创建时从模板复制**并填充占位符（`{任务名称}` / `{工程名}`）；后续原地更新同一文件，不新建版本。

```markdown
# 任务结果摘要 — {任务名称}

> 本文件为任务最新结果态封面（独立文件、无日期后缀、原地更新）。历史变更见同目录 `任务操作记录.md`。
> 职责边界：需求包只描述产品功能与业务行为，**不**包含数据模型 / 接口 / 技术栈等技术设计内容。

## 任务状态
- 当前状态: [需求已确认 / 原型完成 / ...]
- 所属工程: {工程名}（工程公共规则已读取并遵守）

## 需求包清单
| 文件 | 说明 | 状态 |
|------|------|------|
| 01-business-architecture.md | 业务架构与全局约束 | ✅ |
| 02-page-specs.md | 页面功能规格（含状态、业务规则、未决项） | ✅ |
| 产品通用规则.md | 工程级公共规则（角色/权限/通用标准/术语） | ✅ 已读取并维护 |

## 概览
- 端: [移动端 / Web端 / 响应式]
- 功能类型: [参见 01 文档「需求描述」]
- 核心页面: N 个
- 弹窗/浮层: M 个
- 涉及角色: [角色A / 角色B / ...]

## 范围摘要
- 本期范围（做）: [一句话概括，详见 01「范围与非目标」]
- 非目标（不做）: [一句话概括，避免范围蔓延]
- 验收口径: [一句话概括成功标准，详见 01「验收口径」]

## 角色与权限摘要

（详见 01「角色与权限（产品级）」）

## 全局业务规则摘要（产品行为）
- [规则1：如「类目下存在商品时禁止删除」]
（以上均为产品行为描述，不含技术实现；详见 01「全局业务规则」与 02 各页「业务规则」）

## 页面状态覆盖清单
| 页面 | 状态覆盖 | 备注 |
|------|---------|------|
| 页面[1] | 正常 / 空 / 加载中 / 错误 / 受限 | [某状态不适用可标注「无需」] |
共 N 个页面，状态定义均已明确（详见 02 各页「页面状态」）。

## 未决项
| 编号 | 位置 | 问题描述 | 影响 |
|------|------|---------|------|
| OPEN-1 | 页面[2] | [描述] | [对下游影响] |
共 N 项未决（详见 02 各模块「未决项」）。建议在交接下游技术架构 Agent 前闭合。

## 原型状态
> 本任务尚未启用原型生成（第二部分），或由 `pencil-executor` Skill 在原型完成后补充此节。

## 完整性与交接提示
- ✅ 01 页面清单已被 02 全部覆盖（无遗漏页面）
- ✅ 无空页面 / 空模块
- ✅ 需求 ID（页面[N]-M[k]）已贯通 01 / 02
- ⚠️ 未决项: N 项（建议闭合后再交接下游）

交接前请确认：未决项（OPEN-*）已闭合、范围与非目标已对齐。
```

### Step 3：向 任务操作记录.md 追加需求侧条目

> 结构以 `templates/任务操作记录.md` 为单一权威源。**首次创建时从模板复制**并填充 `{任务名称}` 占位符作为表头与首条；后续仅追加条目，不修改历史。
若文件不存在，先创建并写入表头：

```markdown
# 任务操作记录 — {任务名称}

> 本文件为本任务全部操作的忠实流水（只追加、不修改历史）。每条含：计划时间 / 执行内容 / 执行结果 / 复核结果。
```

然后在末尾追加：

```markdown
- 计划时间：YYYY-MM-DD HH:mm
  执行内容：基于 01/02 生成 / 更新任务结果摘要
  执行结果：任务结果摘要.md 已生成 / 更新；涵盖 N 页面 M 弹窗；未决项 K 项
  复核结果：一致 / 待处理（未决项 K 项建议闭合）
```

### Step 4：刷新 产品工程摘要.md 对应行

> 结构以 `templates/产品工程摘要.md` 为单一权威源。**首次创建时从模板复制**并填充 `{工程名}` / `{task_dir}` 占位符；后续原地更新对应任务行，不新建版本。
打开 `document/{工程名}/产品工程摘要.md`：
- 不存在 → 创建并写入：
  ```markdown
  # 工程摘要 — {工程名}

  > 本文件为该工程下所有任务的当前态全貌索引（索引式·轻）。每个任务一行；详情见各自「任务结果摘要.md」。

  ## 任务清单
  | 任务目录 | 当前状态 | 一句话结论 | 详情 |
  |---------|---------|-----------|------|
  | {task_dir} | 需求已确认 | [一句话概括本任务] | → 任务结果摘要.md |
  ```
- 已存在 → 更新 / 新增本任务行（保持索引式：任务目录 · 当前状态 · 一句话结论 · 链接）。
