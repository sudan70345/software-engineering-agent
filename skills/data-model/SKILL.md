## 工作流程

### Step 1：实体识别（按 03 模块分组）
从 03 §2 各模块的功能点（输入/输出/关联数据）与业务规则抽取实体（用户/订单/商品…），识别 1:N / M:N 关系，初步画出 ER 概要。
**实体的「所属模块」继承 03 §1 的模块归纳结果**（M1/M2…）：一个模块的核心业务对象通常对应该模块下的一张或多张表；跨切面模块（鉴权/通知/日志）的实体归其自身模块。§1 实体清单按所属模块分组呈现，与 03 §1 模块划分一一对齐，便于编程智能体按模块定位数据结构。

### Step 2：表与字段设计（含可执行 DDL）
逐表定义字段（类型/约束/默认值/索引），严格遵守 技术通用规则 命名与审计/软删约定；跨任务通用实体改为引用 技术通用规则 第 6 节，本文件只定义本期特有实体与字段。

> ⚠️ **生成中遇不确定必须暂停反问（硬规则）**：写状态机（流转条件 / 触发事件）、表关联 / 事务边界、分表分库等时，若规则不清或存在多种合理实现、或与上游 01/02 及「技术通用规则.md」冲突，必须**立即停止并向用户确认后再落笔**；禁止臆造、禁止仅以「待确认」标记直接出稿等门禁 3 时再发现。确认过程记入 `tech/tech-任务操作记录.md`，必要时登记 TECH-OPEN-*。

每表**必须产出两份可执行 DDL**：`建表语句(DDL)`（CREATE TABLE，含主键/唯一/注释/引擎/字符集）与 `索引语句(DDL)`（CREATE INDEX / ALTER TABLE ADD INDEX），供编程智能体直接执行。DDL 须与上方字段表、索引表完全一致。

### Step 3：关系/状态机/分表
外键关联、事务边界、状态机（字段状态值/流转条件/触发事件）、分表分库规划（如适用）。

### Step 4：写出 04 并确认（门禁3 · 六维）
展示实体关系总览 + 核心表清单，并按**六维**逐表确认（门禁3）：
1. 表（清单/命名/所属模块）
2. 表字段（类型/约束/默认值/说明）
3. 建表语句（CREATE TABLE DDL 可执行、与字段表一致）
4. 索引语句（CREATE INDEX DDL 可执行、与索引表一致）
5. 表关联（外键/关系/事务边界）
6. 字段状态机（状态值/流转条件）
确认 → 进入 tech-delivery（收口）。
