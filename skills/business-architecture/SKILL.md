## 工作流程

### Step 0：前置检查

确认当前系统目录和文件归属：
- 系统目录：`document/{项目名}/{系统名}/`
- 输出目录：`prd/`（prototype-agent 独占）
- 本 Skill 负责生成：`系统要求规范.md` + `系统交互规范.md`（系统级）+ 项目级通用规则（通用异常处理.md / 通用校验规则.md，如不存在则创建）

### Step 1：系统级架构沟通

与用户沟通以下内容（参考 AGENTS.md 阶段1话术）：

#### 1a. 系统定位
「这个系统是什么？给谁用？解决什么问题？」
- 一句话定位
- 系统边界（与其他系统的关系、数据依赖、功能边界）

#### 1b. 业务场景总览
「用户在什么情境下要做什么？」
- 场景[S1]：场景名称 + 场景描述
- 场景[S2]：...
- 每个场景记录：涉及的角色、核心流程

#### 1c. 角色与权限
「哪些角色会使用本系统？」
- 从项目级约定（`项目级产品摘要.md` §0.1 通用术语表 / 已建系统的 `系统要求规范.md` §3）读取通用角色定义
- 确认本系统涉及的角色及其特有权限

#### 1d. 非功能需求（NFR）
「性能、安全、可用性有什么要求？」
- 性能：响应时间、并发量
- 安全：权限控制、数据加密
- 可用性：可用率、容错
- 兼容性：浏览器、设备

#### 1e. 模块清单骨架（核心）
「这个系统包含哪些页面/功能模块？」

**沟通方式**：
- 用户描述页面清单（主页面 + 辅助页面）
- 按页面边界划分模块：
  - **主页面[N]** → 独立模块
  - **辅助页面[N-A]**（复杂弹窗） → 归入所属主页面的模块
  - 简单弹窗 → 不独立为页面，归入主页面

**输出**：模块清单骨架表格

| 模块名 | 对应页面 | 核心功能 | 所属场景 | 状态 |
|--------|---------|---------|---------|------|
| 登录模块 | 页面[1] | 账号密码登录 | S1 | ⏸️ 待开始 |
| 商城首页模块 | 页面[2] + 页面[2-A] | 商品浏览、搜索、详情 | S1 | ⏸️ 待开始 |
| 购物车模块 | 页面[3] | 编辑购物车、预览小计 | S1 | ⏸️ 待开始 |

**字段说明**：
- **模块名**：功能域名称 + "模块"（如"登录模块"）
- **对应页面**：页面[N] 或 页面[N] + 页面[N-A]
- **核心功能**：一句话描述
- **所属场景**：场景[Sx]（可多个）
- **状态**：初始为"⏸️ 待开始"

#### 1f. 范围与非目标
「本期做什么，明确不做什么？」
- In-scope：本期范围
- Non-goals：明确不做的功能

#### 1g. 端范围（端覆盖）
「本期覆盖哪种端？」
- Web（浏览器）/ 移动端（小程序·H5·App）/ 双端并存 —— **绝大多数系统只覆盖一种端**
- 单端判定 → 后续 02 页面规格与下游 05 平台差异节均按该端描述，**不设端分支**
- 若有功能只在某一端提供（或明确不做），逐条记录 → 写入 §6.3 表格「说明」列
- 本期不覆盖的端，说明用户诉求的替代路径

> 📌 **端范围属需求范围决策，不是技术实现问题**：某功能在移动端做不做由本阶段（阶段 1）与用户确认，**技术侧（architect-agent）不自行发明端范围**，只按 §6.3 翻译为 05 §7 平台差异。若用户当时未定，登记至系统要求规范 §6.3 并标注「待确认」。

### Step 2：生成通用规则

**判定标准**：
1. **跨系统复用**（全局异常、字段格式校验） → 项目级 `通用异常处理.md` / `通用校验规则.md`
2. **系统内跨模块复用**（按钮/弹窗/表格等组件交互行为） → 系统级 `系统交互规范.md`
3. **用户明确标注为「通用」** → 按上述层级归类

**操作**：
1. **项目级通用规则**（如不存在则创建）：
   - 从 `templates/prototype-agent/project-level/通用异常处理.md` 复制到 `document/{项目名}/通用异常处理.md`
   - 从 `templates/prototype-agent/project-level/通用校验规则.md` 复制到 `document/{项目名}/通用校验规则.md`
2. **系统级交互规范**：
   - 从 `templates/prototype-agent/system-level/系统交互规范.md` 复制到 `document/{项目名}/{系统名}/prd/系统交互规范.md`
3. 根据用户沟通和项目级通用规则，补充本系统特有的内容
4. 填充占位符（{项目名}、{系统名}、{YYYY-MM-DD}）

**产出文件**：
- `通用异常处理.md`（项目级）
- `通用校验规则.md`（项目级）
- `系统交互规范.md`（系统级）

### Step 3：生成 系统要求规范.md

**操作**：
1. 从 `templates/prototype-agent/system-level/系统要求规范.md` 复制模板到 `document/{项目名}/{系统名}/prd/系统要求规范.md`
2. 填充以下内容：
   - §1 系统定位（来自 Step 1a）
   - §2 业务场景总览（来自 Step 1b）
   - §3 角色与权限（来自 Step 1c）
   - §4 非功能需求（来自 Step 1d）
   - §5 模块清单（来自 Step 1e，**骨架版**，仅基本信息）
   - §6 范围与非目标（来自 Step 1f）
   - §6.3 端范围（来自 Step 1g，**必填**：单端 / 双端 + 不覆盖端的替代路径）
3. 填充占位符（{系统名}、{项目名}、{YYYY-MM-DD}）

**注意**：
- §5 模块清单此时仅为骨架，状态均为"⏸️ 待开始"
- 阶段 2 逐模块沟通时，每完成一个模块，回来更新该模块的状态为"✅ 已完成"

### Step 4：展示给用户确认（确认门禁1）

展示系统要求规范摘要（参考 AGENTS.md 确认门禁1）：

```

📋 系统架构概览（阶段1完成）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

系统名：{系统名}
定位：{一句话定位}
端范围：{Web / 移动端 / 双端并存}（§6.3；单端则不设端分支）

业务场景：
  - 场景[S1]：{场景名称}
  - 场景[S2]：{场景名称}
  - ...

  - 登录模块（页面[1]）
  - 商城首页模块（页面[2] + 页面[2-A]）
  - 购物车模块（页面[3]）
  - ...

通用规则：
  ✓ 通用异常处理.md（项目级，已生成）
  ✓ 通用校验规则.md（项目级，已生成）
  ✓ 系统交互规范.md（系统级，已生成）

──────────────────────────────────────────

请确认：
1. 系统定位是否准确？
2. 模块划分是否合理？
3. 是否有遗漏的模块？
```

**用户反馈**：
- 提出修改 → 更新 `系统要求规范.md`，重新确认
- 确认 → 推进到阶段 2（调用 page-specs Skill）

## 通用规则维护（项目级 + 系统级公共规则抽取）

**触发条件**：同一规则/术语/标准在≥2 个模块或系统中出现，或用户明确标注为「通用」

**抽取内容与落点**：
- 异常处理 / 通用UI状态 / 操作反馈 → 项目级 `通用异常处理.md`
- 字段格式 / 长度 / 业务校验 → 项目级 `通用校验规则.md`
- 角色与权限 → 系统级 `系统要求规范.md` §3
- 组件交互行为 / UI 标准 → 系统级 `系统交互规范.md`
- 业务术语 → 项目级 `项目级产品摘要.md` §0.1 通用术语表

**抽取动作**：将通用内容写入上述对应文件，系统/模块文档内改为引用

**维护时机**：新建项目时用于初始化；已有项目时增量补充/修订

> 📌 详细抽取判据与流程详见 `CLAUDE.md §项目公共规则`
