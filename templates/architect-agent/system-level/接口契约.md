> 🔀 **单源形态（当前态）**：**契约优先（Markdown 单源）**——本文件是契约的单一定义处，`03` §2 与 `05` §4 均为引用方。

> ⚠️ **两种形态下引用方写法完全不变**（一律以 `operationId` 为锚点），故形态切换**不需要改动 `03` / `05` / self-check**，可后置实施。

### 0.2 命名映射（唯一约定）

| 层 | 命名 | 示例 |
|----|------|------|
| 数据表字段（04 / DDL） | `snake_case` | `enterprise_name`、`credit_code` |
| 接口 JSON 字段（本文件 schema） | `lowerCamelCase` | `enterpriseName`、`creditCode` |
| 路由路径 | `kebab-case`，资源名用复数 | `/api/v1/customers/{id}` |
| `operationId` | `lowerCamelCase`，`{动词}{业务对象}` | `createCustomer` |

> ⚠️ 该映射只在此处声明一次：`03` 伪代码引用字段时以**表字段名**（snake_case）为准；`05` 引用字段时以**schema 字段名**（camelCase）为准。缺此约定，前后端会各自猜一次。

### 0.3 版本与兼容

- **路径版本**：`/api/v1`（前缀见 `系统级技术规范.md` §3）；仅破坏性变更才升 `/api/v2`

- **废弃流程**：{标记废弃 → 保留过渡期 → 下线}

## 1. 全局约定（全接口复用）

### 1.1 统一响应包络

所有接口返回统一包络 `ApiEnvelope<T>`：

| 字段 | 类型 | 说明 |
|------|------|------|
| code | string | 业务码，`"0"` 表示成功 |
| message | string | 结果描述（成功固定为 `"success"`） |
| data | T | 业务数据（泛型；无数据时为 `null`） |
| traceId | string | 链路追踪 ID |

> ⚠️ 本文件 §3 各接口的「响应 schema」**只描述 `data` 内部结构**，不重复包络字段。

### 1.2 统一分页

- **入参**：`pageNum`（默认 1）、`pageSize`（默认 {N}，上限 {M}）
- **出参**：`data = { total, pages, list }`
- **不分页接口**：`data` 直接为对象或数组，不使用分页字段

### 1.3 统一鉴权

- **Header**：`{如 Authorization: Bearer <token>}`
- **免鉴权接口**：本文件 §3 显式标记「免鉴权」
- **权限隔离模式**（数据域 / 角色隔离）：见 `系统级技术规范.md` §11

### 1.4 统一幂等

- 写接口幂等**业务要求**（哪些操作必须防重复提交）见 `系统级技术规范.md` §8 与 `系统级技术标准.md` §3；幂等键设计与实现方案属**工程基线**，本文件不定义
- 本文件 §2 接口总表的「幂等」列只标记 `是 / 否 / 不适用`
