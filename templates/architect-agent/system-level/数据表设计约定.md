# {系统名} — 数据表设计约定

> 本文件定义**{系统名}系统**所有业务表的**统一数据约定**，只承载「换任何技术栈结论都不变」的内容：系统默认字段与软删除策略。
> ⚠️ **数据技术细节不在此定义**：字符集 / 存储引擎 / 字段类型标准 / 索引命名规范 / 并发锁策略属**数据库技术实现**，由工程基线（数据库配置文件 / DDL 规范）承载；模块 04 建表 DDL 中的字段类型 / 字符集 / 引擎 / 索引名以工程基线为准。
> 📌 **判据**：换成别的数据库 / 技术栈，结论会不会变？会变（类型 / 字符集 / 引擎 / 索引名 / 锁）→ 工程基线；不变（系统字段的存在与语义、软删除策略）→ 本文件。
> 每个模块的 04 数据模型文件仅需关注**业务字段**，系统默认字段通过本约定自动继承。

---

## 1. 系统默认字段（所有业务表必加）

> 本节定义系统字段的**存在与业务语义**；具体字段类型 / 字符集 / 引擎以工程基线为准。

每个业务表**必须包含以下字段**，命名保持一致：

| 字段 | 业务语义 |
|------|---------|
| id | 主键 |
| created_by | 创建人（用户名或用户 ID） |
| created_at | 创建时间 |
| updated_by | 修改人（最后一次修改的用户名或用户 ID） |
| updated_at | 最后修改时间 |
| deleted_at | 逻辑删除时间（不为 NULL 表示已删除） |

---

## 2. 软删除过滤（强制规则）

所有查询默认排除已逻辑删除的数据：

```sql
SELECT * FROM {table} WHERE deleted_at IS NULL
```

> 恢复已删除数据、或需要包含已删除数据的场景，须在对应读接口的「查询语义」（模块 03 §2）中显式声明。
