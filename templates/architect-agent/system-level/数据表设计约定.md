# {系统名} — 数据表设计约定

> 本文件定义**{系统名}系统**所有业务表的统一设计规范。
> 每个模块的 04 数据模型文件仅需关注**业务字段**，系统默认字段通过本约定自动继承。

---

## 1. 系统默认字段（所有业务表必加）

### 字段定义

每个业务表**必须包含以下字段**，且命名和类型完全一致：

```sql
-- 主键
id BIGINT(20) NOT NULL AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID'

-- 审计字段（记录谁创建、谁修改）
created_by VARCHAR(100) COMMENT '创建人（用户名或用户ID）'
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间'
updated_by VARCHAR(100) COMMENT '修改人（最后一次修改的用户名或用户ID）'
updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后修改时间'

-- 逻辑删除标记
deleted_at DATETIME COMMENT '逻辑删除时间（不为NULL表示已删除）'
```

## 2. 数据库连接与字符集

### 全局设置

```sql
-- 创建数据库时
CREATE DATABASE `{database_name}` 
  CHARACTER SET utf8mb4 
  COLLATE utf8mb4_unicode_ci;

-- 创建表时
CREATE TABLE {table_name} (
  ...
) ENGINE=InnoDB 
  DEFAULT CHARSET=utf8mb4 
  COLLATE=utf8mb4_unicode_ci 
  COMMENT='{表中文描述}';
```

---

## 3. 所有 SELECT 必须加软删除过滤

**强制规则**：

```sql
SELECT * FROM {table} WHERE deleted_at IS NULL
```

---

## 4. 索引命名规范

```sql
-- 主键索引
PRIMARY KEY (id)

-- 唯一索引
UNIQUE KEY uk_{table}_{field} ({field})

-- 普通索引
KEY idx_{table}_{field} ({field})

-- 复合索引
KEY idx_{table}_{field1}_{field2} ({field1}, {field2})
```

---

## 5. 常用字段类型标准

| 字段用途 | 类型 | 范围 | 例子 |
|---------|------|------|------|
| 主键 / 外键 | BIGINT(20) | ±9.2×10¹⁸ | user_id, product_id |
| 数量 / 库存 | INT | ±2×10⁹ | inventory, quantity |
| 小整数（状态/等级） | TINYINT | 0-255 | status |
| 价格 / 金额 | DECIMAL(10,2) | 99999999.99 | price, total_amount |
| 名称 / 标题 | VARCHAR(100) | 可变长 | product_name, user_name |
| URL / 路径 | VARCHAR(500) | 可变长 | image_url |
| 时间戳 | DATETIME | 秒 | created_at, updated_at |

## 6. 并发与锁

### 行级锁使用场景

**仅在以下场景使用 SELECT ... FOR UPDATE**：

```sql
-- 场景：库存扣减前需要获取独占锁
SELECT * FROM {table} WHERE id = ? FOR UPDATE;
UPDATE {table} SET inventory = inventory - ? WHERE id = ?;
```
